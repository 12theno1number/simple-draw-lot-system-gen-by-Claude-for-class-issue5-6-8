           │ 標記領獎 / 改回未領獎（#8）

## 3. 需求決策（已與使用者確認）

| # | 問題 | 決策 |
|---|---|---|
| Q1 | 確認前哪些情況可捨棄？ | 不限原因，主持人可直接按「捨棄」；捨棄後人回到籤筒，名額不扣 |
| Q2 | 待確認時能否切換獎項或重新載入？ | 不行。有待確認結果時鎖住切換獎項、匯入檔案、重置；重新整理頁面時，待確認結果自動作廢 |
| Q3 | 被取消的人能否再參加抽獎？ | **同一獎項不能再抽中，其他獎項可以** |
| Q4 | 是否記錄取消原因？ | 要。下拉選單：「不在場」、「資格不符」、「其他」，選「其他」時可補一行備註 |
| Q5 | 重抽怎麼和一般抽獎區分？ | 取消後出現「重抽」按鈕；抽出的結果標記「重抽」並記下它補的是哪一筆紀錄 |
| Q6 | 重抽結果要經過確認嗎？ | 要，和一般抽獎一樣進入「待確認」 |
| Q7 | 重複取消怎麼處理？ | 已取消的紀錄不能再取消（按鈕停用），名額只退一次 |
| Q8 | 誰可以標記領獎？標錯能改嗎？ | 操作頁面的工作人員都能標，可改回未領獎；系統沒有登入，不分身分 |
| Q9 | 領獎記錄什麼？ | 只記領獎時間，不另外收集簽名、電話等個資 |
| Q10 | 已領獎能否取消中獎？ | 不行，必須先改回未領獎才能取消 |
| Q11 | CSV 匯出內容？ | 只匯出正式中獎與已取消的紀錄（待確認的不匯出），新增「狀態」、「是否領獎」、「領獎時間」欄；已取消紀錄以「已取消」標示，方便對帳 |

## 4. 設計

### 4.1 架構與檔案位置（依 ProjectRule.md）

維持「單一頁面、離線可用、匯入 Excel」的架構，不改成 GAS 或後端。

```
claude script/
├── project/
│   ├── index.html          # 由 draw_lots.html 改寫：畫面與事件處理
│   └── lottery-core.js     # 新增：純邏輯（狀態、資格、名額、CSV），不碰 DOM
└── test/
    ├── lottery-core.test.js  # Node 內建 node:test 單元測試
    └── e2e.test.js           # （可選）Playwright 跑完整現場流程
```

把邏輯抽到 `lottery-core.js`，好處是可以在 Node 裡直接測試每一條規則，不用開瀏覽器。`index.html` 用 `<script src="lottery-core.js">` 載入，以 `file://` 開啟時一樣能用。上週的 `draw_lots.html` 保留不動，作為對照。

### 4.2 資料模型

```js
Prize = { id, name, quota, order, note }

Participant = {
  id,          // 學號；若無學號則為 "row-<列號>"（修正 B4）
  name, department, grade
  // 電子郵件不載入（Q9：不收集不必要的個資）
}

WinRecord = {
  id,              // 自動產生的唯一 ID
  prizeId, participantId,
  status,          // 'pending' | 'confirmed' | 'cancelled'
  isRedraw,        // 是否為重抽（Q5）
  replacesId,      // 重抽時補的是哪一筆被取消的紀錄（Q5）
  drawnAt, confirmedAt,
  cancelledAt, cancelReason, cancelNote,   // Q4
  claimed, claimedAt                       // #8、Q9
}
```

「捨棄」的待確認紀錄直接刪除，不保留（它從來不是正式結果）。

### 4.3 核心規則（全部實作在 `lottery-core.js`）

| 函式 | 規則 |
|---|---|
| `remainingQuota(prize)` | `quota − (confirmed 數 + pending 數)`；cancelled 不計入，所以取消即退回名額 |
| `eligible(prize)` | 排除：任何獎項的 confirmed 得主、目前 pending 的人、**在此獎項被取消過的人**（Q3） |
| `draw(prize, n)` | `n = min(n, 剩餘名額, 合格人數)`，建立 n 筆 pending；沿用原本的 `randInt` / `shuffle`（加密亂數、無偏差） |
| `confirm(id)` / `confirmAll()` | 只能作用於 pending，轉成 confirmed |
| `discard(id)` / `discardAll()` | 只能作用於 pending，直接刪除 |
| `cancel(id, reason, note)` | 只能作用於 confirmed 且 `claimed === false`（Q7、Q10），否則拒絕並回傳錯誤訊息 |
| `redraw(cancelledId)` | 抽 1 人，產生 `isRedraw: true, replacesId` 的 pending；一筆取消紀錄只能被補一次 |
| `setClaimed(id, bool)` | 只能作用於 confirmed；true 時記 `claimedAt`，false 時清除 |
| `toCSV(state)` | 依 Q11 輸出；時間格式完整日期（修正 B6）；加 UTF-8 BOM 讓 Excel 正確顯示中文 |
| `isLocked(state)` | 有 pending 或動畫中即為 true（修正 B1、B2、Q2） |

### 4.4 保存（修正 G3）

- 存在 `localStorage['lottery_v2_state']`：`{ version: 2, prizes, participants, records }`。
- 只存 confirmed 與 cancelled，**pending 不存**，所以重新整理時待確認結果自然作廢（Q2）。
- 讀寫都包在 `try/catch` 裡；讀不到時以空狀態啟動，並在畫面提示。
- 每次狀態改變後立即寫入。

### 4.5 畫面調整

1. **① 資料匯入**：匯入 xlsx 後，自動辨識「獎品設定」與「表單回覆」工作表，各自對應欄位（姓名、系所、年級、學號）。手動貼上名單的方式保留，但只有姓名時以列號當 ID。
2. **② 抽獎**：
   - 新增獎項下拉選單，並顯示「剩餘名額 / 總名額」。
   - 抽出後，舞台顯示「**待確認**」標籤，下方列出 `確認`、`捨棄`、`全部確認`、`全部捨棄`。
   - 有待確認結果時，以下操作停用：獎項切換、抽獎、匯入、重置。
   - 移除「抽過不放回」與「全部排序」（B5、B7）。
3. **③ 中獎紀錄**：每筆顯示獎項、姓名、系所、狀態標籤（正式 / 已取消 / 重抽）。
   - 正式且未領獎：`標記已領獎`、`取消中獎`。
   - 正式且已領獎：`改回未領獎`，`取消中獎` 停用並提示「請先改回未領獎」（Q10）。
   - 按 `取消中獎` 時，展開原因選單與備註欄，確認後才生效。
   - 已取消且尚未補位：`重抽` 按鈕；補位後顯示「已由 ○○○ 補位」。
   - 頂端顯示統計：正式 X、已領 Y、未領 Z、已取消 W。
4. **重置**：改為頁面內二次確認（B3）。

### 實作時補充的設計決定

- **補位者也被取消時：** 改由那一筆被取消的補位紀錄繼續重抽，所以同一個名額永遠只會有一個「重抽」按鈕。
- **重抽前名額已被用掉時：** 取消後退回的名額，如果先被一般抽獎用掉，「重抽」會停用並顯示原因。
- **領獎操作不受待確認鎖定：** 待確認期間仍可標記領獎，因為領獎不影響名額和抽獎資格。只有抽獎動畫進行中時才停用。
- **篩選器：** 新增「全部、未領獎、已領獎、已取消」四種篩選，方便活動結束後對帳未領的獎品（#8 情境）。

P0 的實作細節：
- `xlsx-lite.js`：從上週程式原封不動抽出 Excel 讀取器，讓 Node 測試也能讀真正的測試 Excel。
- `lottery-core.js`：`fromWorkbook` 會自動辨識兩張工作表；`pick` 只挑人，`commitDraw` 寫入前會再檢查名額與資格，所以畫面就算和狀態不同步，也寫不進錯誤資料。
- 已有中獎紀錄時，名單會鎖定，避免換名單後參加者 ID 對不上舊紀錄（第 9 節風險的對策）。
- 測試 Excel 複製一份到 `claude script/test/fixtures/` 供測試使用。

## 6. 測試計畫

### 6.1 單元測試 `claude script/test/lottery-core.test.js`

測試資料以「測試用抽獎後台.xlsx」為藍本（18 人、4 個獎項），寫成 JS 常數。

| 測試 | 預期 |
|---|---|
| 抽出後未確認 | 剩餘名額已預扣；`toCSV` 不含此筆；正式名單不含此筆 |
| 捨棄 | 名額恢復；此人回到合格名單 |
| 確認 | 狀態變為 confirmed；此人不再出現在任何獎項的合格名單 |
| 有 pending 時 | `isLocked` 為 true |
| 取消正式中獎 | 名額 +1；其他中獎紀錄不變 |
| 重複取消同一筆 | 第二次被拒絕，名額只 +1 一次（#5 驗收重點） |
| 被取消者 | 不在同一獎項的合格名單中，但在其他獎項的合格名單中（Q3） |
| 重抽 | 產生 `isRedraw` 的 pending，記錄 `replacesId`；同一筆取消紀錄不能重抽第二次 |
| 已領獎者取消 | 被拒絕；改回未領獎後可以取消（Q10） |
| 標記領獎 | 不影響名額與其他紀錄（#8） |
| 保存與還原 | 存檔後還原，confirmed、cancelled、claimed 都保留；pending 不保留 |
| 名額不足 | `draw(prize, 5)` 遇剩餘名額 2 時只抽 2 人；名額 0 時不能抽 |
| 同名不同學號 | 兩人各自獨立，抽中一人不影響另一人（B4） |

### 6.2 現場情境驗證（手動，或寫成 `e2e.test.js` 以 Playwright 執行）

1. **#6**：抽「二獎」1 人，不確認 → 名單、CSV 都沒有此人，獎項選單被鎖住 → 按捨棄 → 名額回到 2/2；再抽 → 確認 → 名額 1/2。
2. **#6 重新整理**：抽出後不確認就重新整理 → 待確認結果消失，名額不變。
3. **#5**：抽頭獎 3 人並確認 → 取消第 2 人（原因：不在場）→ 其他 2 人不變、名額退 1 → 按重抽 → 確認 → 紀錄顯示「重抽，補位 ○○○」→ 再對同一筆按取消，按鈕已停用。
4. **#5 換獎項**：被取消者在「幸運獎」仍可能被抽中，在頭獎則不會。
5. **#8**：抽多人並確認 → 標記其中 1 人已領獎 → 重新整理後仍為已領獎 → 其他人仍顯示未領獎，名額不變 → 對已領獎者按取消，被擋下。
6. **匯出**：CSV 含狀態、是否領獎、領獎時間、完整日期，已取消者標示「已取消」，待確認者不出現。
7. **Bug 回歸**：動畫進行中按重置、編輯名單 → 均無作用（B1、B2）；重置需要二次確認（B3）。

## 8. 不在本輪範圍

- 多裝置同步、後端寫入（#9、#15）：資料僅存在單一瀏覽器。換電腦或清除瀏覽器資料就會遺失，活動結束請記得匯出 CSV。
- 操作歷史紀錄（#10）：本輪只在紀錄上保存時間與原因，不做獨立的操作日誌。
- 資料清理（#2）、投影個資遮蔽（#7）、不同獎項資格（#4）。
- 舊版 .xls 支援、時間戳記欄位解析（B8）。

## 9. 風險

| 風險 | 對策 |
|---|---|
| localStorage 被清除，紀錄遺失 | 統計列旁提示「請定期匯出 CSV」 |
| 匯入的 xlsx 工作表名稱或欄位名稱不同 | 自動辨識失敗時，退回讓使用者手動選擇工作表與欄位 |
| 抽獎中途重新匯入名單，ID 對不上舊紀錄 | 已有紀錄時匯入新名單需二次確認，並提示會清空紀錄 |
